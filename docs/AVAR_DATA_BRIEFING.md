# Справка: аварские словарные данные

Прилагаемый файл: `av-ru_dictionary.json`. Контекст: лексика и сигналы для suggestions аварской клавиатуры iOS. Ниже — только факты, измерения и уже принятые решения. Предписаний по реализации нет.

## 1. Формат файла

- Несмотря на расширение `.json`, это **JSONL** — один JSON-объект на строку. `json.load()` целиком падает на строке 2.
- 22 842 записи (словарные статьи), UTF-8.
- Происхождение: `docs/av-ru.dictionary.jsonl` из репозитория beched/avar-language-expert (первоисточник — репозиторий avar-me/sources, файл `data/av-ru.jsonl`). Лексикографическая основа — аварско-русский словарь Гимбатова (Махачкала, 2006, ≈36 000 статей).

## 2. Поля записи

- `word` — заголовок статьи (22 842). Существуют статьи-омонимы (поле `homonym`); одинаковые строки из разных омонимов при схлопывании несут суммируемые, а не взаимоисключающие сигналы.
- `forms` — 67 225 токенов; падежные и глагольные формы. В 14 статьях заголовок отсутствует в собственном списке `forms`: заголовок дан в б-классе, формы — в в-классе; оба ряда реальны.
- `gender_forms` — у 331 статьи, 993 токена; классные варианты (аниб/анив/аний) — полноценные поверхностные формы.
- `stem` — у 7 161 статьи; обрезки основ с дефисом («аба-», «абазина-»), самостоятельными словами не являются.
- `senses[].text`, `senses[].comment` — русские толкования. `senses[].examples[]` — пары `av`/`ru` (+`labels`). Аварских примеров 36 845. Символ «~» в примерах не встречается ни разу (сокращение заголовка тильдой, типичное для печатной лексикографии, здесь отсутствует — примеры развёрнуты полностью).
- `labels` — пометы; полная инвентаризация их значений не проводилась.
- `see_also` — перекрёстные ссылки на другие заголовки.

## 3. Символьный состав и палочка

- Во всех `word`/`forms`/`gender_forms` — только кириллица и дефис. Латиницы, цифр, `|`, `!` нет.
- Палочка: строчная `ӏ` U+04CF — 30 026 вхождений по множеству уникальных строк; заглавная `Ӏ` U+04C0 — ровно в 30 словах, все — имена собственные с прописной (ГӀагарав, ГӀачинух, ГӀинкъав и их падежные формы), строчных двойников у них в данных нет.
- Unicode NFC не меняет ни одной строки набора. `lower()` штатно переводит U+04C0 → U+04CF.
- Вне этого файла (в аварских текстах и других источниках) палочка встречается девятью символами: `Ӏ ӏ І і I l 1 | !`. Во вводе пользователя возможен любой из них.

## 4. Дефисные заголовки (энклитики)

- 22 статьи с заголовком на «-»; вместе с их формами — 28 уникальных строк.
- Это связанные морфемы: `-ги` (соединительное «и»), `-гури` («же», примыкает только к глаголу), `-гӏаги`/`-ниги` («хоть, хотя бы»), `-лъила` («кажется»), `-ни` («-то»), `-цин` («даже»), `-гӏан` (уподобление по величине) с классными производными `-гӏанаб/-гӏанав/-гӏанай`, `-ада` («тётя») и `-даци` («дядя») — вторые компоненты сложных слов при собственных именах, у них есть падежные формы (`-адаца`, `-дациил`), `-тӏалаяб` («-этажный, -ярусный»).
- В тексте пишутся слитно с опорным словом (васги = «и мальчик»); как отдельные токены в текстах не встречаются.
- В артефакт words v1 не включены (решение проекта). Ценность — как готовый инвентарь для механики «слово + частица».

## 5. Существующий артефакт `avar_words.sqlite` (content_version 1)

Канонизация v1 (`normalization_version = 1`): **NFC + нижний регистр**. Следствия на этих данных: NFC — 0 изменений; регистр схлопнул 5 пар (имена собственные слились со строчными двойниками); вся палочка стала U+04CF.

Состав v1: `word` ∪ `forms` ∪ `gender_forms`, минус 28 дефисных строк: 63 912 → 63 884 → после канонизации **63 879** строк. Дефисные внутри слова оставлены (4 500 слов, напр. «аб-абизе»); минимальная длина 1, максимальная 28 («секретарь-машинисткалъиялъул»).

Схема (точная):

```sql
CREATE TABLE words(
    word TEXT PRIMARY KEY,
    base_score INTEGER NOT NULL DEFAULT 0
) WITHOUT ROWID;
CREATE TABLE meta(key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

`meta` (7 ключей): `artifact=avar_words`, `schema_version=1`, `content_version=1`, `normalization_version=1`, `min_reader_schema=1`, `row_count=63879`, `generated_at=2026-07-31T05:25:12Z`. Контракт: `normalization_version` совпадает с нормализацией рантайма клавиатуры; `min_reader_schema` защищает читателя от артефакта из будущего; `content_version` растёт с каждой редакцией словника.

Верифицировано: сравнение BINARY + WITHOUT ROWID; `EXPLAIN QUERY PLAN` префиксного запроса `word >= ?1 AND word < ?2` даёт `SEARCH words USING PRIMARY KEY (word>? AND word<?)`; вторая строка плана `USE TEMP B-TREE FOR ORDER BY` — сортировка найденного диапазона по `base_score DESC, LENGTH(word)`. 1 000 случайных префиксных запросов — в среднем ~235 мкс. Верхняя граница диапазона строится инкрементом последнего символа префикса. Файл 1 941 504 байта, кодировка UTF-8, `integrity_check: ok`. Пример: префикс «гӏа» → 1 375 совпадений. `base_score` у всех строк = 0 (0 = нейтрально; частотных данных в v1 нет).

## 6. Корпус примеров: измерения по биграммам

Токенизация av-примеров (кириллица + палочка, внутренние дефисы допустимы, NFC + lower, биграммы в пределах одного предложения):

- 106 096 токенов, 26 547 уникальных.
- 58 747 уникальных биграмм; 52 415 (**89%**) встретились ровно один раз; с порогом cnt ≥ 2 остаётся 6 332.
- Топ: «вуго дов» 129; «чи вуго» 51; «бугев чи» 40; «буго досул» 37; «гьечӏев чи» 30; «бан буго» 30.

Тестовые сборки SQLite (WITHOUT ROWID, PK(w1,w2)):

- текстовые пары `(w1 TEXT, w2 TEXT, cnt)` — 2 297 856 Б ≈ 39,1 Б/строка;
- `lex(id, word UNIQUE)` + int-пары — 2 199 552 Б; выигрыш минимален: UNIQUE-индекс `lex` съедает экономию на этом масштабе;
- int-вариант с отсечкой cnt ≥ 2 — 311 296 Б (6 332 строки).

Точечный запрос `WHERE w1 = ? ORDER BY cnt DESC LIMIT 3` при кэше 512 КиБ — ~18 мкс.

## 7. RAM vs диск (SQLite)

- RAM у SQLite ограничена page cache (по умолчанию ≈2 МБ, `PRAGMA cache_size`) плюс накладные расходы соединения; размер файла на RAM почти не влияет — страницы читаются с диска по требованию.
- Замеры выше сделаны при кэше, принудительно зажатом до 512 КиБ.
- Лимит памяти клавиатурных расширений iOS официально не документирован; по общедоступным данным — порядка 60–70 МБ на современных версиях.

## 8. Оценки масштабирования (экстраполяция, не измерено)

- Внешний корпус: дамп аварской Википедии 7,4 МБ (3 711 статей) + Telegram-каналы ≈180K строк (газета «ХӀакъикъат», 2021–2026) ≈ 1,5–2 млн токенов.
- Ожидаемо 600–900 тыс. сырых уникальных биграмм → текстовыми парами ~25–35 МБ, int-парами ~12–18 МБ; после отсечки cnt ≥ 2 — порядка 3–6 МБ. Доля hapax с ростом корпуса снижается.

## 9. Смежные источники

- `main_av.dict` — бинарный словарь клавиатуры Android (LatinIME, формат v202; «Avar Dict by @ohmagaud», locale ru). Декодирован: 261 962 поверхностные формы, все unigram-частоты = 0; содержит 4 192 чисто числовых токена и мусор вида «000гъур»; палочка — U+04CF. Покрытие словоформ ≈4× больше словарного, но набор грязнее и требует фильтрации.
- beched/avar-language-expert: готовая `avar.db` (таблицы `avar_rus`, `rus_avar`, `entries`, `forms`, `senses`; есть колонка `form_norm` с нормализованной палочкой); там же — корпуса из п. 8.
- Онлайн: avar.me (+ бот @avarme_bot), dev.avar.me; датасет словаря Халилова — ids.clld.org/contributions/107.

## 10. Сигналы для `base_score`, обнаруженные в самом файле

- Частота токена по av-примерам (текст чистый, орфографически выверенный, в отличие от веб-корпусов).
- Размер статьи (число `senses`, число `examples`) — лексикографический прайор употребимости; переносим с заголовка на все его формы.
- `labels` — потенциальный понижающий сигнал (диалектное, устаревшее, грубое); инвентаризация помет не проводилась.
- При схлопывании омонимов в одну строку их сигналы складываются.
