# Review: 48 dictionary entries that violate the token contract

Generated by inspecting the shipped `lezgi_words.sqlite` (20 354 rows,
content_version 1). **Nothing has been removed** — this document exists so
the decision can be made deliberately. Until it is, released behavior is
preserved.

Both groups break the canonical token contract (docs/ARTIFACT_CONTRACT.md
§2), which requires at least two Lezgi letters and no internal whitespace.
Both are reachable in the released keyboard today, which is exactly why
they were not touched: removing them changes what users see in the bar.

"Reachable in the bar" was computed the way the released query works — the
three shortest matches for a typed prefix — so it answers "can this row
actually surface", not "does it exist".

## Why one-character entries are not automatically defects

The plan is right to warn against assuming they are invalid. Several are
plausible lexical items rather than alphabet rows: Lezgi has one-letter
particles and interjections, and the runtime's own two-letter floor
(`LearnedWords.isLearnable`) was written for *learning* — to stop a stray
keystroke from being memorized — not as a claim about the language.

The evidence below is mechanical, not linguistic. Deciding which of the 43
are words needs a Lezgi speaker; my recommendation is limited to what the
data shows.

## What the data shows

- All 43 single-character rows correspond exactly to the alphabet as it
  appears in `AvarKeyboardLayout` — every letter of the layout plus every
  long-press digraph, and nothing else. The set is the alphabet, which is
  what an alphabet dump looks like rather than a curated word list.
- Their effect on the bar is systematic: for a one-letter prefix the row
  equal to that letter is the shortest possible match, so it always takes
  the first slot. Typing «к» offers «к» before any real word.
- All 5 phrase rows contain a hyphen-plus-space pattern
  (`кьиляй- кьилиз`), which reads like a reduplication that lost its
  formatting in the source data rather than an intentional phrase entry.
- Tapping a phrase inserts it as one token while the replacement
  arithmetic in `KeyboardModel` counts a single composed word — the
  deletion count and the phrase length disagree.
- **Zero normalized collisions**, both among these 48 and across all
  20 354 rows: removing any of them cannot silently merge into another row.
- The "elsewhere in repo" column shows only incidental matches — layout
  definitions, normalization tables and test fixtures. No code looks these
  rows up by value, so nothing depends on them existing.

## Recommendation (for review, not applied)

1. **Single letters — remove from the word artifact.** They are the
   alphabet, and their only observable effect is to occupy the first
   suggestion slot for every one-letter prefix. If some are genuine
   particles, they should return as reviewed entries with a real
   `base_score`, not as a side effect of an alphabet dump.
2. **Phrases — remove as source-data defects.** Not "migrate to a phrase
   layer": these five are damaged reduplications, and a genuine
   phrase/static-context layer is the static-bigram artifact, which already
   exists and models context properly as pairs.
3. Either change is a **content_version bump only** — no schema change, no
   migration, no code change. It is a one-line edit to the build script's
   validity rule plus a rebuild.
